## 1. 来源、槽位和参数

复用 R2 的可逆槽位实现。A 保持在 slot0。B/C 的主扫、历史体素、校准、位姿、pairwise 双轴、时码、监督 offset 和掩码跟随物理源。GT、anchor、评价参考和原生后处理固定。控制帧按种子 20261126、输入标识和场景的 SHA256 排名选择，取前两个不同场景。正式调用先执行四条原序重复、四条正式交换、四条交换重复，门禁通过后继续余下 196 条。

CPU 实测 checkpoint 的 `agent_embeds` 是 [5,128]，槽 1/2 的对应行最大差 2.126627。每个 cross block 内的 `value_proj` 对各 Agent 共享，四个 block 各持独立参数。采样和权重投影按 Agent×尺度占用不同输出行，四个 block 的槽 1/2 行实际有差异。四次 cross 后还有两次 Ego self-attention。当前证据确定了槽位敏感的结构候选，槽嵌入、采样投影、累积次序及原生设备运行各自的贡献仍待区分。

R2 的 `cross_value_0` 及 `cross_value_query_*` 位于 `value_proj` 之前。R3 将 Tier 2 的实际投影输出以固定查询切片另存。逐条核对历史捕获字段后，确认有 **14/200** 条历史混龄记录可与新交换作完整公共张量配对，另 **186/200** 仅按实际 Tier 1 公共字段比较。4 组控制帧跨槽可比较 R3 新的投影后切片。预计新捕获 182 条仅 Tier 1、26 条 Tier 2，涵盖全部 8 个控制。

冻结原生容差、确切重复判定与输入/环境指纹。208 条输入在现有 native runtime 完成 Torch CPU deep preflight。离线测试通过预算上限、互斥、原子提交、暂停恢复、持久化恢复、重复门禁通过与失败分支、物理张量轴逆变换和监控。测试使用临时目录和 R2 只读捕获，正式目录保持零新增记录。
